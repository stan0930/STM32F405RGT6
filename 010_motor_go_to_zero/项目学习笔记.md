**STM32 步进电机回零项目学习笔记**

本文依据当前工程源码整理，描述当前实现及其预期运行流程。电机每圈 1600 个脉冲、丝杆每圈移动 8 mm、使能电平和方向电平，均采用代码中的约定，需要与实际驱动器和机械结构一致。

**1. 这个项目做什么**

主控是 STM32F405RGT6。程序通过 TIM5 通道 1 输出脉冲，通过 GPIO 设置电机方向、使能驱动器，通过 PB12 接收零点光电开关信号。

当前应用的预期动作是：

```text
上电初始化
    ↓
滑台向手轮方向回零
    ↓
光电开关触发 PB12 下降沿，电机停止
    ↓
主程序确认停止
    ↓
向电机方向运动 10 圈，脉冲频率为 1000 Hz
    ↓
计满 16000 个脉冲，电机停止
    ↓
主程序留在 main() 的空循环中
```

这是一个不使用 RTOS 的裸机程序，主要由顺序执行的应用代码和外设中断配合完成。

这里的 `Int_Motor.c` 承担的是电机控制封装，不能仅凭文件名中的 `Int` 就把整个文件理解成中断服务程序。文件里既有普通函数，也有在中断中调用的回调函数。

各层的关系是：

```text
App_Main.c：决定做什么、先做什么
    ↓ 调用
Int_Motor.c：把电机动作转换成方向、脉冲数、脉冲频率
    ↓ 调用 HAL 函数或操作定时器宏
HAL 驱动：读写外设寄存器
    ↓
GPIO、TIM5 等硬件：实际产生电平和脉冲
```

中断发生时，则由硬件进入 `stm32f4xx_it.c`，经过 HAL 处理，再回调 `Int_Motor.c` 中的用户函数。

**3. 引脚和外设对应关系**

| 引脚 | 工程名称/外设 | 用途 | 当前代码约定 |
|---|---|---|---|
| PA0 | TIM5_CH1 | 向电机驱动器输出步进脉冲 | PWM1、向上计数、高电平有效 |
| PA4 | MOTOR_DIR | 方向控制 | 低：MOTOR_DIR1，电机方向；高：HAND_DIR2，手轮方向 |
| PB2 | MOTOR_EN | 电机驱动器使能 | 高：使能；低：关闭 |
| PB12 | x_zero / EXTI12 | 零点光电开关输入 | 上拉、下降沿中断；低电平表示已在零点 |
| PC12 | UART5_TX | 串口输出 | 115200 波特率 |
| PD2 | UART5_RX | 串口输入引脚 | 已初始化，当前应用没有串口命令接收逻辑 |

`Core/Inc/main.h` 中的定义说明了 PB12 的名称：

```c
#define x_zero_Pin       GPIO_PIN_12
#define x_zero_GPIO_Port GPIOB
#define x_zero_EXTI_IRQn EXTI15_10_IRQn
```

`GPIO_PIN_12` 是位掩码 `0x1000`，不是整数 12。GPIO 初始化时会把 GPIOB 的第 12 脚连接到 EXTI12。EXTI 回调的 `GPIO_Pin` 参数只携带引脚编号对应的位掩码，不携带端口信息。

**4. 从上电到 App_Main()**

```text
芯片复位
    ↓
startup_stm32f405xx.s 中的 Reset_Handler
    ↓
SystemInit()：系统基础初始化
    ↓
__main：C 运行库初始化，初始化全局/静态变量等
    ↓
main()
    ├─ HAL_Init()
    ├─ SystemClock_Config()
    ├─ MX_GPIO_Init()
    ├─ MX_UART5_Init()
    ├─ MX_TIM5_Init()
    ├─ App_Main()
    └─ while (1) { }
```

`HAL_Init()` 建立 HAL 基础环境，包括中断优先级分组、默认 1 ms SysTick 时基以及调用 `HAL_MspInit()`。

`SystemClock_Config()` 使用 8 MHz 外部晶振，通过 PLL 配置出 168 MHz 系统时钟。APB1 为 42 MHz；由于 APB1 分频不为 1，TIM5 的输入时钟为 84 MHz。

`MX_GPIO_Init()` 配置方向输出、使能输出、PB12 外部中断，并使能对应 NVIC 中断。

`MX_UART5_Init()` 初始化日志串口。

`MX_TIM5_Init()` 配置 TIM5 的时基、PWM 通道、PA0 复用以及 TIM5 的 NVIC 中断。这里只完成配置，真正开始输出脉冲要等后续调用 `HAL_TIM_PWM_Start_IT()`。

当前工程中，TIM5 的外设时钟与 NVIC 配置放在 `tim.c` 的 `HAL_TIM_Base_MspInit()`；PA0 复用配置放在 `HAL_TIM_MspPostInit()`。

**5. App_Main() 是应用流程入口**

`source/App/App_Main.c` 当前代码：

```c
void App_Main(void)
{
    Int_Motor_Init();
    Int_Motor_Reset();

    while (Int_Motor_GetState() != MOTOR_STOP);

    Int_Motor_Start(MOTOR_DIR1, 10, 1000);
}
```

逐句理解：

| 代码 | 作用 |
|---|---|
| `Int_Motor_Init()` | 把软件中的电机状态设为 MOTOR_INIT |
| `Int_Motor_Reset()` | 检查零点输入；未在零点时，开启回零运动 |
| `while (... != MOTOR_STOP);` | 空循环等待，直到状态变为停止 |
| `Int_Motor_Start(MOTOR_DIR1, 10, 1000)` | 向电机方向运动 10 圈，脉冲频率 1000 Hz |

`while` 末尾的分号表示循环体为空，下一句 `Int_Motor_Start()` 在循环结束后才执行。

等待期间 CPU 在反复读取状态，但中断仍然可以打断主程序。PWM 由定时器硬件持续输出，PB12 触发后，中断回调可以停止电机并改变状态。

`Int_Motor_Reset()` 和 `Int_Motor_Start()` 都是在配置硬件并启动运动后返回，不会在函数内部等待全部运动结束。应用只显式等待了回零；启动 10 圈运动后，`App_Main()` 返回，程序进入 `main()` 的空循环，后续停止由 TIM5 中断完成。

**6. 电机参数和软件状态**

`Int_Motor.h` 定义了三个主要类型：

```c
// 方向
MOTOR_DIR_T
    MOTOR_DIR1
    HAND_DIR2

// 距离
MOTOR_DISTANCE_T
    target_step
    current_step

// 状态
MOTOR_STATE_T
    MOTOR_INIT
    MOTOR_RUN
    MOTOR_STOP
```

它们被组合到 `MOTOR_PARAMS_T`，并在 `Int_Motor.c` 中创建变量：

```c
static MOTOR_PARAMS_T motor;
```

含义如下：

- `motor.motor_dir`：记录设置的方向。
- `motor.motor_distance.target_step`：本次目标脉冲数。
- `motor.motor_distance.current_step`：软件累计的脉冲计数。
- `motor.motor_state`：软件记录的当前状态。

文件作用域的 `static` 表示变量只在当前 `.c` 文件中可直接访问，其他模块通过对外函数操作它。该变量具有静态存储期，未显式初始化的成员在程序启动时会被清零。

当前结构体没有单独保存速度；速度由 `Int_Motor_SetSpeed()` 换算后写入定时器寄存器。

当前代码没有单独的回零状态。上电时执行 `Int_Motor_Init()` 后为 MOTOR_INIT；回零函数未改变它，直到光电开关触发停止，才变为 MOTOR_STOP。普通定距运动则会设置为 MOTOR_RUN。

**7. 普通运动：方向、距离、速度、启动**

对外接口：

```c
void Int_Motor_Start(MOTOR_DIR_T dir,
                     double distance_turn,
                     double speed);
```

三个参数分别表示方向、目标圈数和每秒脉冲数。`speed` 在这个接口中不是 mm/s，也不是转/分。

当前执行顺序：

```text
motor.motor_state = MOTOR_RUN
    ↓
打印 start
    ↓
PB2 输出高电平，使能驱动器
    ↓
Int_Motor_SetDir(dir)：设置 PA4
    ↓
Int_Motor_SetDistance_turn(distance_turn)：计算目标脉冲数
    ↓
Int_Motor_SetSpeed(speed)：设置 ARR 和 CCR1
    ↓
HAL_TIM_PWM_Start_IT(&htim5, TIM_CHANNEL_1)
    ↓
定时器持续输出脉冲，并开启通道 1 比较中断
```

公开函数 `Int_Motor_Start()`、`Int_Motor_Stop()` 等供应用层调用；带 `static` 的方向、距离、速度设置函数只供 `Int_Motor.c` 内部使用。

距离换算采用以下参数：

```text
1 圈 = 1600 个脉冲
1 圈 = 360°
1 圈 = 滑台移动 8 mm
```

对应公式：

```text
圈数 → 脉冲数：target_step = distance_turn × 1600
角度 → 脉冲数：target_step = distance_angle ÷ 360 × 1600
毫米 → 脉冲数：target_step = distance_mm ÷ 8 × 1600
```

目前 `Start()` 使用圈数换算；毫米和角度换算函数已经写好，但调用被注释了。代码对圈数、角度、距离做了上限限制，分别相当于 30 圈、10800°、240 mm。

按代码参数，10 圈对应 16000 个脉冲、80 mm。脉冲频率为 1000 Hz 时，匀速运动理论用时约 16 秒，线速度约为 5 mm/s。

这里的“步数”是按驱动器配置换算的脉冲数，不一定等于电机固有整步数。软件也没有编码器反馈，因此它记录的是输出脉冲，无法直接确认机械部分是否丢步。

**8. TIM5 为什么能控制速度**

`tim.c` 的主要配置：

```c
htim5.Init.Prescaler = 84 - 1;
htim5.Init.CounterMode = TIM_COUNTERMODE_UP;
htim5.Init.Period = 1000 - 1;

sConfigOC.OCMode = TIM_OCMODE_PWM1;
sConfigOC.Pulse = 500;
sConfigOC.OCPolarity = TIM_OCPOLARITY_HIGH;
```

几个寄存器的分工：

| 寄存器 | 作用 |
|---|---|
| PSC | 预分频，决定 CNT 每秒计数多少次 |
| CNT | 当前计数值 |
| ARR | 自动重装载值，决定计数周期 |
| CCR1 | 通道 1 比较值，决定 PWM 高电平宽度及比较事件时刻 |
| SR | 记录更新、捕获/比较等事件标志 |
| DIER | 控制相应事件是否允许产生中断或 DMA 请求 |

本工程的计数频率：

```text
f_CNT = 84 MHz ÷ (PSC + 1)
      = 84 MHz ÷ 84
      = 1 MHz
```

所以 CNT 每 1 μs 增加 1。

初始配置对应：

```text
CNT 从 0 数到 999，一周期共 1000 次计数
PWM 周期 = 1000 μs = 1 ms
PWM 频率 = 1000 Hz
CCR1 = 500 → 高电平约占周期的 50%
```

在当前向上计数、PWM1、高电平有效的条件下：

```text
CNT < CCR1       → 高电平
CNT 达到 CCR1    → 高电平结束，并产生比较事件
CNT 超过 ARR     → 回到 0，进入下一周期
```

`Int_Motor_SetSpeed()` 的核心换算是：

```c
double arr_reg = 1000000.0 / speed;

__HAL_TIM_SetAutoreload(&htim5, arr_reg - 1);
__HAL_TIM_SetCompare(&htim5, TIM_CHANNEL_1, arr_reg / 2.0);
```

即通过改变周期控制脉冲频率，并把占空比维持在约 50%。寄存器写入的是整数，所以某些频率只能近似实现，例如回零设置的 6000 Hz。

PWM 由定时器硬件自动产生，不需要 CPU 每次调用 GPIO 函数翻转电平。当前速度设置采用直接切换频率，没有加减速曲线。

**9. 第一条中断链：TIM5 计脉冲，到数停止**

```text
TIM5 的 CNT 达到 CCR1
    ↓
硬件置位 CC1 比较标志；CC1 中断已使能
    ↓
CPU 根据启动文件中的向量表进入 TIM5_IRQHandler()
    ↓
HAL_TIM_IRQHandler(&htim5)
    ↓
检查标志和中断使能，清除标志，记录当前通道
    ↓
判断通道 1 为输出模式
    ↓
HAL_TIM_OC_DelayElapsedCallback(htim)
    ↓
HAL_TIM_PWM_PulseFinishedCallback(htim)
    ↓
进入 Int_Motor.c 中的用户实现
```

CPU 中断入口位于 `Core/Src/stm32f4xx_it.c`：

```c
void TIM5_IRQHandler(void)
{
    HAL_TIM_IRQHandler(&htim5);
}
```

HAL 处理函数位于 `Drivers/STM32F4xx_HAL_Driver/Src/stm32f4xx_hal_tim.c`。

```c
itflag   = htim->Instance->SR;    // 发生了哪些事件
itsource = htim->Instance->DIER;  // 使能了哪些中断
```

对通道 1，HAL 先检查 CC1 标志和 CC1 中断使能，再清除标志，并设置：

```c
htim->Channel = HAL_TIM_ACTIVE_CHANNEL_1;
```

接下来读取 CCMR1 中的 CC1S 位：非零走输入捕获回调，为零走输出分支。当前工程使用 PWM，走输出分支。

工程设置 `USE_HAL_TIM_REGISTER_CALLBACKS = 0U`，所以编译时选择直接调用同名回调函数；如果该宏为 1，HAL 则通过句柄中的函数指针调用回调。

当前输出分支依次调用 OC 和 PWM 两个回调，不会进一步根据 PWM/OC 用途只选择一个。默认 OC 回调为空，用户重写了 PWM 回调，所以电机计步逻辑在 PWM 回调中执行。

```c
void HAL_TIM_PWM_PulseFinishedCallback(TIM_HandleTypeDef *htim)
{
    if (htim->Instance == TIM5)
    {
        if (motor.motor_state == MOTOR_RUN)
        {
            motor.motor_distance.current_step++;

            if (motor.motor_distance.current_step >=
                motor.motor_distance.target_step)
            {
                Int_Motor_Stop();
            }
        }
    }
}
```

当前回调只检查 TIM5，没有检查活动通道；目前只用通道 1 可以对应上。以后使用同一定时器的多个通道时，还需要结合 `htim->Channel` 判断。

HAL 完成回调后把 `htim->Channel` 设为 `HAL_TIM_ACTIVE_CHANNEL_CLEARED`，表示本次通道回调结束，不代表停止定时器。

这里由 `CNT == CCR1` 的比较事件触发，正常连续输出时每周期一次。计数器溢出产生的更新事件对应另一条处理分支及 `HAL_TIM_PeriodElapsedCallback()`。

**10. 第二条中断链：PB12 检测零点，触发停止**

`gpio.c` 中把 PB12 配置为上拉、下降沿中断，并开启 NVIC：

```c
GPIO_InitStruct.Pin = x_zero_Pin;
GPIO_InitStruct.Mode = GPIO_MODE_IT_FALLING;
GPIO_InitStruct.Pull = GPIO_PULLUP;
HAL_GPIO_Init(x_zero_GPIO_Port, &GPIO_InitStruct);

HAL_NVIC_SetPriority(EXTI15_10_IRQn, 0, 0);
HAL_NVIC_EnableIRQ(EXTI15_10_IRQn);
```

EXTI12 使用共享入口 `EXTI15_10_IRQHandler()`，因为 EXTI10～EXTI15 共用这个中断向量，没有单独的 `PB12_IRQHandler()`。

```text
光电开关触发，PB12 从高电平变为低电平
    ↓
硬件置位 EXTI12 中断挂起标志
    ↓
CPU 进入 EXTI15_10_IRQHandler()
    ↓
HAL_GPIO_EXTI_IRQHandler(x_zero_Pin)
    ↓
检查 EXTI12 挂起标志，清除标志
    ↓
HAL_GPIO_EXTI_Callback(GPIO_PIN_12)
    ↓
Int_Motor_Stop()
```

CPU 中断入口在 `stm32f4xx_it.c`，该调用由 CubeMX 按配置生成：

```c
void EXTI15_10_IRQHandler(void)
{
    HAL_GPIO_EXTI_IRQHandler(x_zero_Pin);
}
```

HAL 中的通用处理函数已由 ST 实现：

```c
void HAL_GPIO_EXTI_IRQHandler(uint16_t GPIO_Pin)
{
    if (__HAL_GPIO_EXTI_GET_IT(GPIO_Pin) != RESET)
    {
        __HAL_GPIO_EXTI_CLEAR_IT(GPIO_Pin);
        HAL_GPIO_EXTI_Callback(GPIO_Pin);
    }
}
```

这里检查的是中断挂起标志，不是引脚当前电平。清除标志表示处理本次记录，不会改变引脚电平或禁止后续中断。STM32F4 的 EXTI 挂起位通过写 1 清除。

用户处理逻辑在 `Int_Motor.c`：

```c
void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
    if (GPIO_Pin == x_zero_Pin)
    {
        Int_Motor_Stop();
    }
}
```

当前实现只要 PB12 下降沿触发，就执行停止，不限于回零状态。

本工程 PB12 的抢占优先级为 0，TIM5 为 2；数值越小，优先级越高，因此零点中断可以抢占 TIM5 中断。

**11. 回零与普通运动的区别**

| 项目 | 普通运动 Start | 回零 Reset |
|---|---|---|
| 方向 | 参数指定 | 固定 HAND_DIR2 |
| 速度 | 参数指定 | 设置为约 6000 个脉冲/秒 |
| 距离 | 先计算目标脉冲数 | 不设置目标脉冲数 |
| 主要停止条件 | 软件脉冲计数达到目标 | PB12 零点光电开关触发 |
| 当前函数是否设为 MOTOR_RUN | 是 | 否，也未设置专门的回零状态 |

`Int_Motor_Reset()` 首先读取 PB12：

```c
if (HAL_GPIO_ReadPin(x_zero_GPIO_Port, x_zero_Pin) == GPIO_PIN_RESET)
{
    printf("zero hehe\r\n");
    return;
}
```

如果未在零点，则使能驱动器、设置手轮方向、设置速度、启动 PWM，然后返回。

在当前上电流程中，回零期间软件状态仍为 MOTOR_INIT，所以 TIM5 中断仍会发生，但 PWM 用户回调不会执行 MOTOR_RUN 分支里的步数累加和定距停止。到零后由 PB12 中断停止。

**12. 停止函数做什么**

```c
void Int_Motor_Stop(void)
{
    motor.motor_state = MOTOR_STOP;
    HAL_GPIO_WritePin(MOTOR_EN_GPIO_Port, MOTOR_EN_Pin, GPIO_PIN_RESET);
    HAL_TIM_PWM_Stop_IT(&htim5, TIM_CHANNEL_1);
    printf("end\r\n");
}
```

它记录停止状态、关闭驱动器使能、停止 TIM5 通道 1 的 PWM 与比较中断，并打印日志。

普通运动到数和零点触发最终都调用这个停止函数。

这里没有把 `current_step` 清零；HAL 的 PWM Start/Stop 接口也不会代替用户管理这个软件计数。

**13. 中断入口、HAL 处理函数、用户回调如何区分**

| 层次 | 定时器例子 | GPIO 例子 | 主要职责 |
|---|---|---|---|
| CPU 中断入口 | TIM5_IRQHandler | EXTI15_10_IRQHandler | 由向量表指定，进入对应外设处理 |
| HAL 通用处理 | HAL_TIM_IRQHandler | HAL_GPIO_EXTI_IRQHandler | 检查标志、清除标志、分发回调 |
| 用户回调 | HAL_TIM_PWM_PulseFinishedCallback | HAL_GPIO_EXTI_Callback | 执行计步、停止等应用逻辑 |

HAL 为回调提供默认弱定义，例如：

```c
__weak void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
    UNUSED(GPIO_Pin);
}
```

默认实现不做业务处理，`UNUSED()` 用于避免未使用参数的编译警告。

在自己的 `.c` 文件中定义同名、同参数、不带 `__weak` 和 `static` 的函数，并让该文件参与编译链接，链接器就会优先使用用户实现。工程中同一个用户回调保留一个实现，不要在不同 `.c` 文件里重复定义。

回调仍在当前中断上下文中执行，不是另开一个线程或任务。它完成后返回 HAL，再从中断返回原来被打断的位置。

定位一个新中断时可以按以下顺序阅读：

```text
引脚/外设初始化
    → NVIC 使能
    → stm32f4xx_it.c 中的 IRQHandler
    → HAL 的 IRQHandler
    → 需要用户实现的 Callback
```

**14. 串口日志和 DWT 工具**

`usart.c` 把 `printf()` 的字符输出重定向到 UART5：

```text
printf()
    ↓
fputc()
    ↓
HAL_UART_Transmit(&huart5, ..., 1, 1000)
    ↓
PC12 / UART5_TX 输出字符
```

串口参数为 115200、8 位数据、无校验、1 位停止位，即 115200 8N1。

当前主要日志为 `start`、`end`，以及上电已在零点时的 `zero hehe`。UART5 虽配置了 RX 引脚，但当前应用没有读取串口命令，也没有 UART5 接收中断处理链。

`Com_DWT.c` 提供 DWT 周期计数器初始化和微秒忙等待延时，通过 CPU 周期数估算经过的时间。它已经加入 Keil 工程，但当前应用未调用它；当前电机脉冲由 TIM5 产生。

**15. 当前代码需要留意的实现问题**

这些问题来自当前源码阅读，未通过开发板运行验证；本次梳理没有修改控制代码。

1. **上电时已经在零点，会一直等待。** `Int_Motor_Init()` 先设置 MOTOR_INIT，随后 `Reset()` 发现 PB12 已为低电平就直接返回，没有设置 MOTOR_STOP。应用的空循环会一直等不到停止状态。已经为低电平也不等于后续会产生新的下降沿。需要让“已在零点”的分支明确报告回零完成，或让应用根据返回结果决定是否等待。

2. **重复运动前没有清零 `current_step`。** 第一次使用时依赖静态变量的启动清零；第一次运动结束后计数仍然保留，再次调用 `Start()` 会在旧计数基础上累加。每次普通运动应在启动 PWM 前初始化本次计数。

3. **回零缺少明确状态。** 目前依靠上电时的 MOTOR_INIT 跳过普通计步逻辑。如果在 MOTOR_RUN 状态下调用 `Reset()`，仍可能执行旧目标对应的计步停止逻辑。可以增加 MOTOR_HOMING 等状态，把普通运动和回零的停止条件明确分开。

4. **主程序与中断共享的状态没有 `volatile` 限定。** 主程序循环读取状态，中断会改写状态，需要让编译器按要求读取共享状态；可以对共享状态采用适当的 `volatile` 限定。`volatile` 本身不保证多个字段操作的原子性，运动参数配置还要考虑中断打断的时机。

5. **停止回调中包含阻塞串口打印。** `Stop()` 在中断中被调用时，`printf()` 也在中断中逐字节阻塞发送。它会延长中断处理；当前 SysTick 优先级低于这两个外设中断，若发送异常依赖 HAL 时基超时，时基还可能无法及时推进。可以由中断记录事件，让主程序输出日志。

6. **回零等待没有超时，运动参数缺少完整校验。** 当前没有回零最大时间/距离，也没有完整处理零、负速度和非正距离；`speed == 0` 会进入除零运算。后续完善时应明确这些输入和异常的处理方式。

7. **精确启停还需处理定时器初始状态。** 当前 ARR 与 CCR1 预装载已使能，新值通常在更新事件时生效；运动函数也未显式复位 CNT 或清理启动前的比较标志。要保证每次启动的首个脉冲时序，需要一并检查预装载生效、CNT、标志位和启动顺序，而不能只看稳态频率公式。
